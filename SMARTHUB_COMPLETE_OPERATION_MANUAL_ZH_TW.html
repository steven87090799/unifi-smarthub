1. 使用前必讀

（總覽與起步：README.md、docs/README.md）

SmartHub 是家庭／內網基礎設施的集中管理面板。瀏覽器只連到 SmartHub；SmartHub 再以伺服器端帳密連接 UniFi、UCG、UGREEN NAS、WiiM、CyberPower UPS、AdGuard Home 與 Linux 主機。因此不會把上游設備密碼發到瀏覽器。

高風險操作：限制用戶端、PoE 斷電重開、臨時威脅 IP 封鎖、Docker 容器動作、AdGuard 保護開關／服務政策、WiiM 控制、連線設定與還原，都會改變外部系統或本機設定。請先確認目標、帳號角色和回復方式。
真實設備與展示資料：某些未設定整合會呈現未設定、空狀態或示範資料。畫面正常、單元測試通過、mock 可回覆，均不等於已在真實 UPS、NAS、UniFi 或音響驗證。
標示意思建議
唯讀只查詢或改變本機視圖。可安全瀏覽，仍可能對上游設備發出讀取請求。
會寫入改變 SmartHub 設定或上游設備。確認欄位與目標，觀察成功／錯誤訊息。
管理員需要 admin Session，且寫入 API 檢查 Origin、CSRF 和輸入。readonly 帳號不可執行。
立即生效儲存後由目前程序重新載入或重排。不用重啟，但連線失敗仍須排查。
需 recreateDocker 建立容器時固定讀取的 NAS Monitor 連線／信任參數。儲存後依畫面提示重新建立容器。

2. 架構與資料流

（系統結構：docs/reference/architecture.md、docs/reference/backend-map.md）

瀏覽器 SPA

public/index.html 是頁面骨架；public/js/app.js 負責資料讀取、按鍵、圖表與輪詢；登入、PWA、Web Push 與安全動態按鍵另有獨立模組。

主服務

server.js 組裝 Express 路由、整合、排程、健康檢查與安全中介層。可測試的細節放在 server/。

持久資料

db.js 與 SQLite WAL 保存歷史、事件、報表 claim、政策、Web Push、audit 與 instance lock；data/smarthub.db 是 runtime 資料，不用 JSON 全檔覆寫。

外部整合

伺服器呼叫 UniFi、UCG SSH、NAS／Monitor、WiiM、UPS、AdGuard、Linux SSH 與通知服務。整合失敗通常只影響對應頁面，不會讓主服務未就緒。

信任與生命週期

  • 除健康端點與登入資產外，API 需 Session 或相容 Basic Auth；異動再需 admin、同源 Origin、CSRF 與欄位驗證。
  • DATA_DIR 有 2 秒 heartbeat、8 秒租約的 instance lock；兩個程序不可共用同一資料目錄。失去 owner 時程序安全關閉。
  • 同名週期工作不重入；報表又以 SQLite claim、lease、deadline、fencing 和 retry 管理。正常關機會停止新工作、flush 資料並關閉資源。
  • NAS Monitor Docker socket 等同宿主機 root 權限，預設不啟用，操作與日誌各有獨立 allowlist，SmartHub／broker 容器永久 protected。

3. 登入、權限與安全

（後端安全契約：docs/reference/backend-map.md、docs/operations/OBSERVABILITY.md）

項目控制內容影響
管理員登入PANEL_PASSWORD；名稱可用 admin。可讀取資料並進行受保護的設定／外部異動。
唯讀登入PANEL_READONLY_USERNAME、PANEL_READONLY_PASSWORD，密碼必須不同。可監看，不執行 admin action；前端 dispatcher 也會拒絕這些動作。
記住登入狀態Session 預設 12 小時；勾選時預設 30 天。僅在可信私人裝置使用；登出會使目前 Session 失效。
登入節流失敗 5 次後，預設冷卻 300 秒。降低猜密碼風險；請不要反覆重試。
登入頁健康快照/api/public/system-health。僅最小記憶體摘要、節流保護；不探測設備，也不應含密碼或 Session。

請僅將服務放在可信任內網；遠端使用 VPN 或可信反向代理。PANEL_TRUSTED_PROXIES 只能寫明確 IP／CIDR，不能設為 true、* 或 hop count。反向代理外部 origin 不同時才設定 PANEL_ALLOWED_ORIGINS。

5. 14 個頁面、按鈕與控制項

（頁面與設備操作：docs/reference/frontend-map.md、docs/reference/backend-map.md）

以下列出實際 UI 控制意圖。時間範圍按鈕均只重新查詢／重繪對應歷史，不會刪除資料；CSV 下載只匯出目前端點允許的歷史。

5.1 總覽 Overview

控制項用途與影響
UCG／NAS／WiiM 釘選卡與「查看詳情」唯讀 顯示裝置即時摘要；點擊導向／平滑捲動到相對細節，不發送控制命令。
資安戰情速覽唯讀 讀取威脅摘要；進入資安頁可查看、篩選與管理封鎖。
趨勢範圍：1 小時、6 小時、24 小時、3 天、7 天、30 天唯讀 改變 setTrendRange() 查詢窗口。30 天需要歷史保存天數足夠。
網路裝置埠對照唯讀 顯示交換器／AP 埠與連接設備；資料來自 UniFi。

5.2 UCG-Ultra

控制項用途與影響
CPU、溫度、WAN、交換器／AP／埠狀態唯讀 讀 UCG SSH／UniFi 資料；若 SSH 失敗會反映連線錯誤或空資料。
歷史：10 分、30 分、2 時、6 時、24 時、7 天唯讀 切換 UCG 歷史圖窗口。
下載 CSV唯讀 下載目前 UCG 歷史資料，未修改 SQLite。
溫度異常事件唯讀 顯示偵測到的事件；實際門檻／取樣由後端設定控制。
每台裝置服務封鎖會寫入管理員 為指定 IP 建立 AdGuard 時段政策；需填 IP、時區、分類、星期與起訖時間。儲存會寫入政策並由 reconcile 套用；移除會還原政策所管理的規則。

UniFi 裝置遙測：UCG 頁的裝置卡只讀專用 snapshot 與 SQLite 近 24 小時歷史，畫面 refresh 不直接查 Controller 或建立 SSH。只有 Controller 明確提供的溫度，或 MAC allowlist Device SSH 讀到的真實 thermal 值才顯示數字；沒有真值時顯示「不支援」，stale 時保留最後成功資料並清楚標示。Readonly 可讀遙測端點，但不能修改 Device SSH 設定。

5.3 客戶端 Clients

控制項用途與影響
搜尋框唯讀 即時依名稱、MAC、IP 等篩選已載入清單。
客戶端列／詳細視窗唯讀 開啟設備資訊、流量與歷史。
限制／解除限制會寫入 呼叫 UniFi device restrict；會讓指定 MAC 失去或恢復網路存取，並記錄存取控制歷史。操作前核對 MAC 與使用者身分。
流量排行、存取控制時間軸唯讀 顯示排序與歷史，不會變更設備。

5.4 資安 Security

控制項用途與影響
自動防禦切換會寫入管理員 儲存安全設定；開啟後後端依自動防禦掃描頻率處理符合條件的威脅。先確認隔離規則與救援存取。
「歸零重新統計」會寫入 重置前端／安全統計基準；不是刪除原始 UniFi 威脅來源。
搜尋、嚴重度、類別、1／3／7／30 天唯讀 篩選目前威脅表格與時間範圍。
匯出 CSV唯讀 匯出過濾後可見威脅資料。
複製來源 IP唯讀 將 IP 放入剪貼簿。
臨時封鎖／提前移除會寫入管理員 新增或刪除 SmartHub 專用 UniFi IPV4_ADDRESSES 清單項目。只接受公網 IPv4、強制有到期時間；防火牆 policy 必須事先指向這個專用清單，勿混入人工規則。

5.5 WiFi、雲端站點與工具

頁面／控制項用途與影響
WiFi SSID 廣播開關會寫入 更新指定 UniFi WiFi network；會使該 SSID 開啟或關閉。先確認 network ID 與是否會中斷使用者。
訪客 SSID、密碼、產生 QR會寫入管理員 同源產生 WiFi QR；SSID 最長 32、密碼 8–64。QR 不送往第三方，但仍不可在公開畫面曝光。
雲端：Sites／Devices／Hosts／SD-WAN tabs唯讀 切換 UniFi Site Manager 資料分類；目前與一般前端輪詢設定共用、預設 5 秒。上游 API 仍可能 rate limit，勿將畫面更新誤當成即時設備控制。
工具：WAN 網速測試會寫入外部作業 要求 UCG 執行 speed test；有流量與 CPU 負擔，短時間不要重複觸發。
工具：PoE 斷電重開會寫入管理員 需填 Switch MAC 和 Port Index，對該埠重新供電，會使 AP／攝影機／電話等離線重啟；確認設備及現場影響後才按。

5.6 NAS

控制項用途與影響
即時摘要、硬碟／Volume、SMART 詳情唯讀 顯示 UGOS 或 NAS Monitor 資料；點硬碟可開 SMART 視窗，關閉不改資料。
歷史：10 分、30 分、1 時、6 時、24 時、7 天唯讀 切換 CPU、記憶體、流量、儲存與溫度圖的查詢窗口。
Docker 重新整理、容器動作會寫入管理員 重新整理只讀清單；start／stop／restart 等實際動作只對已啟用、已標記、符合 allowlist 的容器可用。受保護容器不可操作。
Docker 日誌、複製日誌唯讀管理員 讀取另一份 log allowlist 許可的日誌；日誌可能含敏感資訊，複製後妥善處理。
新增／更新警報閾值會寫入 指定 metric、比較（高於／低於）與門檻；會影響 NAS 警報判斷與通知。
刪除警報閾值、日誌層級／隱藏自身切換、確認警報會寫入 刪除會停止該 metric 閾值判斷；日誌控制多為畫面篩選；ack 只確認 SmartHub 看到的警報，不會修復 NAS 原因。

5.7 AdGuard、Linux、通知

控制項用途與影響
AdGuard「立即更新」唯讀 立即重新讀取統計與最近記錄。
AdGuard 保護開關會寫入管理員 啟用／停用 AdGuard protection；全網 DNS 攔截行為可能立即改變。
Linux 歷史：1 時、6 時、24 時、7 天唯讀 切換 Linux CPU／溫度／記憶體歷史。
通知頻道 tabs唯讀 切換 Discord、Telegram、Generic Webhook 設定表單。
Web Push 訂閱／取消會寫入 在本瀏覽器註冊或刪除推播 subscription；VAPID 三項必須由部署環境設定。
偵測 Telegram Chat ID唯讀 依 Telegram Bot 可讀更新找 Chat ID；需先由目標帳號／群組與 bot 互動。
儲存、測試推播、重新整理紀錄會寫入 儲存管道設定、發出測試或讀取最近投遞 log。Webhook 應支援 idempotency key；請勿將 secret 顯示在截圖。

5.8 WiiM Amp

WiiM 頁同時有監看與遙控。所有命令由伺服器政策檢查；高風險命令需要精確確認。未接真機時，不可把畫面回應視為實體音響已變更。

群組每個按鈕／欄位的作用
播放列會寫入 上一首、播放／暫停、下一首、停止、靜音、音量 −／＋與音量滑桿會送 WiiM 播放命令。進度條拖曳是 seek；先預覽位置，放開才提交。
播放模式會寫入 依序為一般、全部循環、單曲循環、隨機；直接改音響 loop mode。
來源會寫入 Wi‑Fi、Bluetooth、Line‑in、Optical、Coaxial、USB Disk 切換輸入來源，可能中斷目前播放。
圖表唯讀 顯示點、平滑曲線、live scroll 只改圖表呈現；10 分、30 分、2 時、12 時、全部改查詢窗口；CSV 下載；「清除歷史」會寫入 會刪除 WiiM 歷史，請先匯出。
警報門檻會寫入 CPU／board 溫度門檻保存後影響警報判斷與通知。
Audio tab會寫入 聲道平衡滑桿、SPDIF 延遲、播放模式 gain JSON 都會對設備送命令；讀取 gain config 為唯讀。JSON 格式錯誤不應提交。
EQ tab會寫入 EQ On／Off、載入 preset、設定 band 會改 DSP；載入 preset、查詢 EQ 狀態／band 為唯讀。先記錄原 preset 以便復原。
Source tab會寫入 以底層 switchmode 直接切來源；與上方來源按鈕目標相同。
Bluetooth tab會寫入 掃描秒數後開始探索、清除探索結果、連線／斷線指定 MAC；取得結果、歷史、配對狀態為唯讀。
Stream tab會寫入 URL 播放、加入／建立群組、啟用／停用 Cast 都會改音響狀態；Squeezelite／wlan 狀態查詢為唯讀。
System tab會寫入 reboot、同步時間、排程關機（0 取消）、LED／實體按鍵開關、LCD JSON 都直接改裝置。查詢關機倒數為唯讀。
配件與資訊唯讀 重新整理遙控器／配件與取得設備資訊，只讀回目前狀態。

5.9 UPS

控制項用途與影響
即時輸入／輸出、電池、負載、剩餘時間、狀態唯讀 讀取選定來源（PPB、NUT、pwrstat、pmset 或 auto）；斷電時輸入電壓為零是正常事件訊號。
電壓範圍：10 分、30 分、1 時、6 時、24 時、7 天；下載 CSV唯讀 改變 UPS 歷史圖窗口或匯出資料。
負載範圍：10 分、30 分、1 時、6 時、24 時、7 天唯讀 僅切換負載圖窗口。
電力品質與 PPB 原生事件唯讀 顯示 SmartHub 偵測事件與 PPB 同步資料；第一次成功同步只建立初始化狀態，不應將所有歷史事件當成新通知。

5.10 完整互動控制索引（含細部按鍵）

設備連線設定：「儲存並立即套用」

密碼欄留空代表保留現有值，不是清除。一般欄位寫入部署實例的 config/.env 並立即套用；請確認容器有權對 config 目錄 atomic rename。NAS Monitor 欄位為容器建立期固定，見 需 recreate。

區塊／欄位控制內容風險／注意
UCG SSH：UCG_IP、SSH_USER、SSH_PORT、SSH_PASSWORD、WAN_IFACEUCG 硬體遙測與 WAN 介面顯示。錯誤位址／帳密使 UCG 頁讀取失敗；SSH 有 12 秒命令期限與輸出上限。
UniFi Local：UNIFI_CONTROLLER_URL、帳號、密碼客戶端、WiFi、威脅、防禦與 PoE 等本地 API。變更會立即影響寫入目標；先確認 URL、HTTPS 與最小權限帳號。
Site Manager：UNIFI_API_KEY雲端 Sites／Devices／Hosts／SD-WAN。選填；沒有有效 key 時應顯示未設定／展示資料。
Integration API：URL、Key、TLS verify、Site UUID、Threat List UUID／Name臨時威脅來源 IP 封鎖。預設驗證 TLS；非 loopback HTTP 被拒。專用 list 只供 SmartHub 管理。
WiiM：WIIM_IP所有音響狀態與命令。先確認 IP 不會指向他人設備。
UPS：UPS_SOURCE、NUT host/name、pwrstat path、PPB host/port/user/password、TLS verify/insecure/CA決定 UPS 資料來源與信任鏈。Docker 以 PPB 時用 host.docker.internal:3052，不可填容器內 127.0.0.1。僅 PPB_TLS_INSECURE=true 會停用驗證；優先使用一般檔案的絕對 CA 路徑。
NAS：host、port、user、passwordUGOS 直連的 NAS 監看。缺少任一必要欄位時，對應功能不可用。
NAS Monitor：mode、URL、API keyDocker、進階 NAS 資料與事件串流。需 recreate URL／key／信任設定在 Docker creation 固定，完成後依 pending 提示 recreate；不要把 port 8000 暴露公網。
AdGuard：URL、舊 host/port、帳密、允許 HTTP、TLS verify、CADNS 統計、保護開關與政策。非 loopback HTTP 需顯式 opt-in，帳密會明文傳輸；HTTPS 預設驗證，優先私有 CA。

UniFi Device SSH（僅管理員可見）：UNIFI_DEVICE_SSH_PORT、UNIFI_DEVICE_SSH_USER、password、target MAC 與 Host Key 是選配的真實溫度 fallback。最多 32 台，且必須是 Controller-known、online、Literal IP；固定唯讀命令最多兩條並行。Host Key 格式為 mac=SHA256:...。密碼、MAC 清單與 fingerprint 只顯示是否設定，安全備份也不包含。

伺服器取樣設定：「儲存伺服器設定」

欄位控制內容調整效果
Device Active Frontend Poll Sec可見頁向後端更新的一般裝置畫面頻率。小＝畫面更即時、HTTP 更多；不直接決定歷史取樣。
Device Active／Idle Backend Sample Sec一般裝置有人看／無人看時後端真實取樣與歷史寫入頻率。小＝設備與 SQLite 負荷更高；collector 完成後才排下一次，不會重疊。
Heartbeat Sec、Active Lease Sec瀏覽器續租與逾時離線判定。lease 必須大於 heartbeat；太短可能誤判閒置、太長延後降頻。
Watcher Sec、Auto Defense Sec通知掃描與自動防禦掃描。小＝事件更快但更多整合讀取；自動防禦未開啟時不執行隔離。
UPS 前端／Active／Idle／History／PPB events／PPB Active／Idle分別調整 UPS 畫面、真實樣本、歷史大型讀取、PPB 原生事件畫面與背景同步。UPS 不共用一般裝置 idle 值；請保留足夠間隔避免來源負載。
Toast Sec右下通知存在秒數。只改 UI 體驗。
History Flush Min一般遙測記憶體佇列批次寫入 SQLite 的周期。小＝較快落盤、更多 I/O；UPS 關鍵事件與 NAS 警報不等待此批次。
History Keep Days所有趨勢／UCG／NAS／UPS／WiiM 歷史保留天數。短＝省磁碟但可看的最長曲線縮短；30 天圖至少保留 30 天。

7. 更新、心跳與取樣模型

一般頁面更新與後端設備取樣是兩層不同機制。一般前端工作與一般焦點取樣共用設定，預設 5 秒；UPS 有獨立設定，狀態預設 3 秒。可見分頁每個都有獨立 session lease；切頁、背景或 lease 到期只釋放自己的 scope，不會停止另一個使用者／分頁。

範圍可見時預設閒置／背景時
總覽與一般裝置資料5 秒；heartbeat 5 秒。前端非共用工作停止；一般後端 sampler 回到 600 秒預設。
UCG／NAS／WiiM／Linux 歷史與即時資料5 秒；所有一般值可在設定頁調整。使用一般後端閒置頻率，預設 600 秒。
雲端 Site Manager／ISP5 秒；共用一般前端設定。不建立額外設備 sampler；仍須留意上游 API rate limit。
UPS真實來源 3 秒，歷史與 PPB 事件各 10 秒。樣本預設 10 秒、PPB 同步 60 秒，可在設定頁覆寫。

scope 對應：總覽送 trend, ucg, nas, wiim, ups；個別裝置只送自己的 scope；客戶端、資安與雲端只送 trend。general 不是設備 sampler，不能把所有設備強制加速。最多 1,000 sessions、每 session 8 scopes，逾期優先清理，再 LRU 淘汰。完整頻率表見 docs/operations/POLLING-INTERVALS.md。

8. 資料、備份與還原

  • Docker 正式資料權威是 volume 掛載到 /app/data；不要以 repository 內 JSON 整檔覆蓋歷史。
  • SQLite 使用 WAL；完整離線備份要先停止服務，再一併保存 DB、-wal、-shm 和 config/.env（以受保護方式保存）。
  • 線上「安全備份」是設定備份，刻意不含 secret；它不是災難復原的完整資料庫備份。
  • 還原前先下載現況備份、檢查 staged restore 狀態與目標版本；不要在不確定 schema／來源時上傳檔案。
  • 歷史資料保留由 History Keep Days 清理；WiiM 的「清除歷史」是個別破壞性操作，請先匯出 CSV。

本機隔離演練可使用 http://127.0.0.1:3000；正式對外必須以前置 Caddy／Nginx 終止 HTTPS，再反向代理至內部 port，不可把 http://<NAS IP>:3000 當作 production 入口。config/ 建議 0700、config/.env 必須 0600，且根目錄不要留下第二份 .env。Docker 容器內上游不能填 localhost／127.0.0.1。

開發與假資料

SMARTHUB_ENV_FILE=config/.env npm start
# 另一個終端：純假資料預覽（port 3005）
node server-mock.js

正式不可變發布

  1. 確認工作樹完全乾淨並完成安全備份，再執行完整 gate：
    npm ci
npm run check:js
npm test
npm run check:css
npm run test:smoke
SOAK_DURATION_MS=90000 npm run test:soak
npm audit --audit-level=low
git diff --check

docker compose --env-file config/.env config --quiet

  2. 執行 npm run release:build。它拒絕任何 staged、unstaged、untracked 差異，從 git archive HEAD 建立 SmartHub 與 NAS Monitor 成對不可變映像。
  3. 把輸出的 revision image tags（或 registry immutable digests）填入 config/.env 的 SMARTHUB_IMAGE、NAS_MONITOR_IMAGE。

# 只有需要 NAS Monitor 時

  5. 比對執行中的 image ID 與 release JSON，執行 health、登入角色、SQLite、整合與重啟驗證，並保留發布紀錄。

NAS Monitor profile

預設沒有啟用。只有必須看／控 Docker 時才設定 COMPOSE_PROFILES=nas-monitor 或加 --profile nas-monitor。它以非 root 運行但可寫 Docker socket 仍等同宿主 root；必須先啟用 mutations／logs，並設定各自的 allowlist／managed label。

回滾

  1. 把 SmartHub 與 NAS Monitor 同時改回上一組已驗證的 image tag／digest。
  2. 使用同一個 project、config dir、env file、profile 執行 up -d --no-build --pull never。
  3. 重新檢查 health、角色、SQLite、重要整合、重啟與還原狀態。

11. Debug、診斷與故障排除

安全的第一輪證據

docker compose --env-file config/.env ps
docker compose --env-file config/.env logs -f unifi-smarthub
docker compose --env-file config/.env logs unifi-smarthub | grep 'ERROR\\|CRITICAL'
curl -fsS http://127.0.0.1:3000/health
curl -fsS http://127.0.0.1:3000/health/ready
curl --user admin http://127.0.0.1:3000/api/system/status
現象檢查順序處置原則
/health 成功、/health/ready 503System Diagnostics、SQLite、worker stuck、volume 權限與 instance lock。外部整合故障通常不會使 readiness 503；優先查 DB／worker。
某一整合頁空白／失敗設定頁連線欄位、container 到設備網路、TLS／CA、服務 logs、對應端點。不回印密碼／Token；確認 Docker 裡的 host 不等於 localhost。
設定已存、NAS Monitor 未更新查看 connections status 和 pending recreate。Monitor URL、API key、信任設定為 creation-scoped，依提示 recreate 容器，不用期待熱更新。
UPS 無資料檢查 UPS_SOURCE、PPB host/port、容器 DNS、TLS、NUT 可達性。PPB 建議 host.docker.internal:3052；私有 CA 優於關閉 TLS。
按鍵無法寫入／403確認 admin 而非 readonly、重新登入、同源 origin、CSRF、欄位格式與 allowlist。不要為了繞過 403 關閉保護；先找拒絕原因。
Docker 按鈕無法使用確認 profile、Monitor health、mutations/logs enabled、allowlist、managed label、protected label。設計上拒絕不在清單與受保護容器，這不是故障。
資料不夠即時／負載太高確認頁面是否可見、heartbeat scope、lease、輪詢設定、collector 是否重疊。不要把所有間隔一律設 1 秒；只調必要 scope，並觀察上游／SQLite 負載。

可觀測性設定

LOG_LEVEL 可為 DEBUG、INFO、WARNING、ERROR、CRITICAL；追蹤 task lifecycle 暫設 DEBUG，完成後回 WARNING／INFO。LOG_FORMAT=json／LOG_JSON=true 適用送往 Loki、ELK、OpenSearch。即使 DEBUG，Authorization、cookie、Session、password、token、API key、CSRF、webhook 仍應被遮罩，看到疑似敏感資訊要視為事件處理。

錯誤代碼分類：SYS-*（程序／資源）、DB-*（資料庫）、API-*（驗證／輸入）、WORKER-*、EXT-*（外部整合）。權威清單在 observability/error-codes.js。

  • 新增／修改前端可見 API 或設定欄位時，同步 server.js、server-mock.js 與對應契約測試。
  • 新增寫入控制時同時處理 readonly、admin、CSRF、Origin、輸入驗證、確認、錯誤回復與 audit；不能只在前端隱藏按鈕。
  • 修改 Tailwind class 後執行 npm run build:css；提交前以 npm run check:css 確認生成 CSS 同步。
  • UI script CSP 僅允許 'self'；不要加入 inline script、inline event handler、unsafe-inline 或 unsafe-eval。
  • 歷史資料沿用 db.js／SQLite。長時間工作需要 process／lease 邊界；只取消 JS thread 不等於 hard kill。

14. 操作檢核表

首次上線

  1. 設定強管理員密碼，若要唯讀帳號則設定不同密碼。
  2. 設定 config 目錄權限與可信內網／VPN 邊界。
  3. 逐一填連線設定；每填一種整合即檢查該頁、logs 與 diagnostics。
  4. 先測試通知，再開啟自動防禦、Docker mutation 或服務封鎖等寫入功能。
  5. 做一次安全備份及一次完整離線備份演練。

每次高風險按鈕前

  1. 確認目前是 admin、目標 IP／MAC／container／port 正確。
  2. 確認執行後的可見影響：斷網、重啟、DNS 放行／封鎖、音訊中斷或資料刪除。
  3. 確認恢復步驟：解除限制、提前移除封鎖、重啟容器、還原設定或匯入 CSV。
  4. 執行後查看 toast、對應頁、通知紀錄、System Diagnostics 與必要的真實設備狀態。

手冊維護規格：新增頁面、按鍵、API、設定欄位、部署步驟或安全邊界時，應同步更新本檔，並保持與 README.md、docs/reference/backend-map.md、docs/reference/frontend-map.md、.env.example 和測試契約一致；每新增、移動或刪除 Markdown 時，也必須更新第 15 章。
