計算公式

從 滿分 100 開始，把「過去 24 小時」每一起 IPS/IDS 攔截事件的扣分加總後扣掉。只看近 24 小時，所以威脅停止後分數會隨時間自動回升。

每起事件的扣分 = 嚴重度 × 類別倍率

嚴重度基礎分

  • 高危 HIGH−4 分
  • 中 MEDIUM−2 分
  • 低 LOW / 其他−1 分

類別倍率

  • Malware / DoS×1.5
  • 其他類別×1.0

例：1 起高危 Malware = 4 × 1.5 = 扣 6 分

等級對照

A 優良 90–100 B 良好 75–89 C 普通 60–74 D 警戒 40–59 F 危險 <40< /span>

💡 目前是 F 通常代表 24 小時內攔截了大量（或多起高危）攻擊 —— 這是 IPS 有在運作、把攻擊擋下的紀錄，不代表你被入侵。想看分數回升可把時間拉開觀察，或在下方事件表確認攻擊是否已被 BLOCKED。

                            兩種間隔有什麼不同？
                        

                        

                            

                                
🖥️ 前端輪詢間隔

                                
你「開著網頁時」，瀏覽器每隔多久向後端要一次最新資料來更新畫面。


                                    • 只影響你眼前畫面的即時度；關掉網頁就完全停止。

                                    • 存在這台瀏覽器，每個裝置可各自設定（手機、電腦互不影響）。

                                    • 改了立即生效，不用按儲存。

                                    • 數字越小 → 畫面越即時，但越頻繁打後端。

                            

                            

                                
⚙️ 伺服器端取樣間隔

                                
後端在背景「不管有沒有人看」都會執行的排程。


                                    • 影響長期歷史記錄與自動化（寫入趨勢資料庫、掃描威脅推播）。

                                    • 存在伺服器，所有人共用、對整個系統生效。

                                    • 改了要按儲存，後端立即重排。

                                    • 這裡的「趨勢取樣」跟前端無關，是後端寫入歷史檔的頻率。

                            

                        

                        
💡
                            兩者的橋樑是「心跳」（在前端輪詢裡）：心跳讓後端知道有人在看，因而切到「有人瀏覽」的高頻取樣；沒心跳就用「閒置」頻率。

                    


                    
                    

                        

                            
🖥️ 前端輪詢間隔（秒）

                            
                        

                        
你開著網頁時，各項資料多久向後端要一次。改了立即生效、只存在這台瀏覽器。每格下方說明它控制哪些畫面。
                        

                        

                    


                    
                    

                        
⚙️ 伺服器端取樣間隔（秒）

                        
後端背景排程，無論誰連線都套用（存於伺服器）。每格下方說明它控制什麼。

                        

                            

                                
                                
有人開著網頁時，後端多久把一筆「線上客戶端數 /
                                    24H 威脅數 / ISP 延遲」寫進歷史檔。決定趨勢圖的解析度。

                                
秒

                            

                            

                                
                                
沒人看網頁時多久取樣一次。設長一點（如 1800
                                    秒＝30 分）可避免無人使用時仍一直打 API。

                                
秒

                            

                            

                                
                                
收到最後一次心跳後，幾秒內仍算「有人在看」。超過就切到上面的閒置頻率。設太短切太快、太長會多打一陣子。

                                
秒

                            

                            

                                
                                
後端多久檢查一次有沒有新威脅 / NAS 嚴重警報要推播（Discord/Telegram）。設短推播更即時。
                                

                                
秒

                            

                            

                                
                                
後端多久掃一次威脅事件，自動隔離受感染的內網設備（需先在「資安」頁開啟自動防禦聯動，否則此排程不動作）。

                                
秒

                            

                            

                                
                                
後端多久記錄一筆 UPS
                                    電壓/電池/負載到持久化歷史。此排程不做閒置降頻——斷電與電壓紀錄無人瀏覽也要持續記錄（本地指令，成本低）。

                                
秒

                            

                            

                                
                                
右下角小通知框（IPS
                                    攔截、儲存成功等）顯示幾秒後自動消失。

                                
秒

                            

                            

                                
                                
一般遙測先放記憶體，每幾分鐘用一個 SQLite transaction 寫入 SSD。NAS 日誌推播、UPS 斷電等關鍵事件不會被延遲。

🔌 如何接上真實 CyberPower UPS？(NUT
                            架構已就緒)

                        

                            
後端會依 UPS_SOURCE 自動嘗試三種來源（詳見 cyberpower-ups-api.md）：

                            
1. NUT（建議）：brew install
                                    nut → ups.conf 設 [cyberpower]
                                    driver=usbhid-ups port=auto → 關閉 PowerPanel 與 macOS 節能器的 UPS 監控（釋放 USB HID
                                獨佔）→ brew services start nut。後端即自動以 upsc
                                    cyberpower@localhost 讀取。

                            
2. pwrstat：安裝官方 PowerPanel 後，後端自動回退呼叫 pwrstat -status。

                            
3. pmset：macOS 原生 HID（僅電池容量/充電狀態，無電壓數據）。
                            

                            
環境變數：UPS_SOURCE(auto)、NUT_HOST(localhost)、NUT_UPS_NAME(cyberpower)、PWRSTAT_PATH。Docker 部署時 NUT 建議跑在宿主機，容器透過 NUT_HOST=host.docker.internal 連線。
